Reading: uncorrected reuse loses about half the F1 here, and only 5 of 100 answers match full prefill word for word. Temporal questions (category 2) take the biggest hit, 0.254 → 0.075. In several cases the reused model answers "the conversation does not provide any information" when full prefill finds the date, which fits the idea that a chunk cached alone hasn't linked its content to the other chunks. This is the gap methods 2-4 are supposed to close, and E1 measures how well they do.

Things to flag honestly

Our full-prefill F1 (0.244) is well below AgentKVShift's 0.509. They use LiCoMemory, a memory system with generated metadata; we use plain BM25 conversation chunks. Our answers average 13.8 words for a "short phrase" prompt, which pulls token F1 down. We report absolute and relative gaps, so the comparison is still fair within our setup. The full 1,986-question baseline will show whether conv-26 is typical.
Category 3 is weak even with full prefill (0.097 on 13 questions). These are open-domain questions that need inference beyond the text, and n is small. Worth checking on the full run before reading anything into it.

Timing finding · cuDNN found and fixed

Profiling (jobs 6092365, 6092397, 6092445, H100) found that PyTorch picked cuDNN's attention kernel, which rebuilds its execution plan for every new sequence length. Every LoCoMo prompt has a new length, so each call paid ~40-45 ms of plan building. We now exclude cuDNN by default (SDPA_BACKENDS in kvreuse/forward.py).

Median prefill, 12 distinct prompt lengths (~2.3K tokens)

Without cuDNN overhead the reuse speedup shows up: re-positioning is 2.6× faster than full prefill (29.9 vs 78.9 ms). There's more headroom: a fresh 67-token forward still takes ~19 ms against a ~4 ms weight-read floor, because the hand-written layer loop launches ~1,500 small kernels per call. CUDA graphs or torch.compile are the next speedup.

The E1 sweep (6092366) and baselines (6092367) were submitted before this fix. Their F1 is valid; their prefill_ms is not and won't be used. E2 timings will come from the fixed code.
