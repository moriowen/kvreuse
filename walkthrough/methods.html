The four correction methods

All four run through the same loop (page 2, step 6). They differ only in which tokens get recomputed at which layers. Each one bets that the reuse error lives in a different place.

Token × layer view

Columns are prompt tokens (a toy prompt: short system prefix, three chunks of 20 tokens, a question). Rows are decoder layers. Pick a method and drag the budget.

system prefix (exact, cached) reused KV (re-rotated) recomputed fresh reused + estimated offset question (always fresh)

Budget accounting: one formula for everyone

budget = Σlayers |reusable tokens with fresh QKV| / (32 layers × reusable tokens)

Layers run in full before the selection layer, and the selection layer itself, are charged in full. CacheBlend and AgentKVShift have to compute QKV for every token at layer 1 to know which tokens deviate, so a "15%" CacheBlend actually costs (2 + 30 × 0.15) / 32 ≈ 20%. The grid's readout shows this charged number next to the knob value.

This matters for the comparison: papers often quote only the selection ratio. Charging every method the same way is one of the things our study adds. The code is PrefillResult.budget() in kvreuse/forward.py.

Method by method

method 1

Re-positioning only

Re-rotate keys, recompute nothing except the question. Bet: the missing cross-chunk attention doesn't matter much. Cheapest possible. It's also the only method vLLM can serve without scheduler changes, so its quality cost is what the connector pays.

methods.py · Reposition (and RepositionAligned for the vLLM 16-token-block version)

method 2

Boundary (EPIC)

Recompute the first k tokens of every chunk, at every layer. Bet: a chunk cached alone treats its first tokens as an attention sink, which is wrong once it sits mid-prompt. Static choice, no selection layer. Sweep k = 4, 8, 16, 32, 64.

methods.py · EPIC · paper: arXiv 2410.15332

method 3

Dynamic selection (CacheBlend)

Run layers 0 and 1 for every token. At layer 1, rank chunk tokens by how far their fresh V is from the reused V. Keep the top ratio (global across chunks) and recompute only those from then on. Bet: the error is sparse but could be anywhere.

methods.py · CacheBlend · follows the released code (V only, one selection, global ratio), not the paper. Paper reports 2.2-3.3× lower TTFT within 0.02 F1 on RAG.

method 4

Offset correction (AgentKVShift)

Same layer-1 check, but per chunk: top tokens by K deviation and by V deviation become probes. Probes are recomputed. At each later layer the chunk's mean probe error is added to every other token in that chunk. Bet: most of the error is one shared shift per chunk.

methods.py · AgentKVShift · our reimplementation of Algorithm 1 (no public code). Paper: 0.491 vs 0.509 F1 for full recompute on LoCoMo, Mistral-7B, 10% budget. Main comparison point.

Sanity properties the tests enforce

Every method at 100% budget equals full prefill.
Reuse error is real (nonzero) for re-positioning and shrinks as the budget grows.
Selection layers are charged in full by the budget formula.
AgentKVShift's offsets actually move non-probe KV.
Recompute set can only shrink with depth (a plan returning a token outside S raises).
All on a tiny random Mistral on CPU, in under a second: tests/test_e0.py.
