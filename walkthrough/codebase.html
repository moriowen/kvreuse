How runs flow on PACE

Code is rsynced from the laptop to ~/scratch/kvreuse (home is only ~15 GB). Jobs are chained with Slurm afterok, so a failed E0 cancels everything after it.

prepareCPU · ~1 min
→
e0H100 · gate
→
smoke100 questions
→
baselines1,986 questions × 2
then, by hand:
array: E14 tasks × 4 configs
array: E22 tasks × 8 configs
e5vLLM venv
Two venvs. vLLM 0.27.1 pins its own torch, so it gets a separate Python 3.12 venv. Our package is installed there with --no-deps.
Two code copies. ~/scratch/kvreuse is frozen while E1 and baselines run (each config rereads the code). New work runs from ~/scratch/kvreuse-dev.
Cluster limits. 50 submitted jobs per user (array tasks count, shared with other coursework) and a cap on GPU × requested minutes. Hence packing several configs per array task.
Model weights. Ungated mirror unsloth/mistral-7b-instruct-v0.3; its weight shards have the same SHA-256 as the official gated repo. Every summary records the model id.

Commands

# laptop
.venv/bin/python -m pytest                        # E0 logic, CPU, <1 s

# PACE login node
bash pace/setup.sh                                # venv, LoCoMo, tests
bash pace/submit.sh --with-baselines              # prepare -> e0 -> smoke -> baselines
sbatch --array=0-3 --export=ALL,PER_TASK=4 pace/array.sbatch pace/jobs/e1.txt
sbatch --array=0-1 --export=ALL,PER_TASK=8 pace/array.sbatch pace/jobs/e2.txt

# one config by hand (inside a GPU job)
python scripts/run_eval.py --method agentkvshift --budget 0.1 --kl
python scripts/analyze.py results/full_top10_bf16.jsonl results/*.jsonl --out results/table.md
